Silkie 配置¶

Silkie reads silkie.conf from its own configuration directory, normally ~/.config/silkie/. It does not automatically read kitty's configuration or use KITTY_CONFIG_DIRECTORY.

Configuration paths¶

Set SILKIE_CONFIG_DIRECTORY to use a different directory. Otherwise, Silkie searches for silkie.conf in the following order and uses the first file whose directory is writable:

  • $XDG_CONFIG_HOME/silkie/, when XDG_CONFIG_HOME is set;

  • ~/.config/silkie/;

  • ~/Library/Preferences/silkie/ on macOS;

  • silkie/ under each directory in XDG_CONFIG_DIRS, in order.

If no configuration exists, Silkie creates $XDG_CONFIG_HOME/silkie/ or ~/.config/silkie/. System defaults come from /etc/xdg/silkie/silkie.conf and are read before the user configuration. Relative includes, themes, kitten configuration files, and profiles use the Silkie configuration directory. The Settings window writes settings.conf there, which is read after silkie.conf.

Use --config /path/to/file.conf to load a file explicitly, or --config NONE to skip configuration files. To reuse existing kitty settings, copy them to silkie.conf or add an explicit include, for example:

include ../kitty/kitty.conf

The configuration syntax and inherited settings are described in kitty's configuration reference. The paths above are specific to Silkie.

Environment variables lists the environment variables that Silkie reads and the ones it sets for the programs running in it.

Quitting on macOS¶

Silkie does not bind Cmd-Q to quit by default. To explicitly enable it, add this to silkie.conf:

map cmd+q quit

The application menu's Quit command remains available without a keyboard shortcut unless you configure one.

Spatial display¶

On macOS, View → Spatial Display switches between ordinary rendering, stereo content that follows the head, and an anchored terminal wall. Settings place XREAL 1S support under Experimental and untested, disabled by default. Enable experimental_xreal_1s yes to use side-by-side output or XREAL tracking. Red/blue output without tracking does not require that opt-in. Spatial settings include side-by-side and red/blue output, independent positive and negative divergence limits, and a 2^X divergence multiplier with X from -6 to 6 in 0.1 steps. Fractional pixel depth scales with the physical eye resolution, including Retina backing scale. Negative divergence and vertical phase are disabled by default and require explicit user configuration. Applications can assign depth to text and graphics while leaving unmarked content flat. See Spatial display and depth for XREAL setup, configuration, the optional text attribute, and current tracking support.

Numeric controls enforce the setting's domain: opacity stays within its documented range, dimensions and durations are nonnegative, and documented negative sentinels and signed scroll multipliers remain available. Cursor HDR brightness and HDR headroom start at 1× and step by 0.1, with no invented upper bound. Composite values retain their complete text rather than losing optional parameters to a numeric widget.

SSH agent forwarding¶

Set ssh_agent_forwarding yes to offer the local SSH agent over the terminal channel. Odin Seat and Skiff can keep a stable SSH_AUTH_SOCK while the provider follows the attached terminal. See SSH agent transport for permissions, connection lifetime, fallback behavior, and protocol details.

电子纸与配色切换¶

Silkie knows which monitor each window is on, and treats a window on an e-paper monitor as such, even when the operating system thinks it is an ordinary display, as it does for every e-paper monitor seen so far. It knows some e-paper monitors by the model in their EDID, never by serial number (among them the ONYX BOOX Mira and Mira Pro, several DASUNG Paperlike models and the Modos Glider). Declare any other with monitor_info in silkie.conf, by its model, connector, EDID manufacturer and product code, or a part of its description:

monitor_info MIRA253 kind=eink color=gray bits=4
monitor_info "OBX:0x0011" kind=eink color=gray
monitor_info DP-7 kind=eink color=rgb

kitten @ ls 的 display 字段显示 Silkie 掌握的各窗口显示器信息。窗口移到另一台显示器时，silkie --debug-rendering 会记录这些信息。可用 monitor-identifiers.py 在 macOS 或 Linux 上列出已连接显示器的标识，以填写 monitor_info。

这些设置仅作用于该显示器上的窗口。窗口移到普通显示器后，稍等片刻即可恢复常规显示；移回时会重新应用这些设置。

电子纸（kind=eink）和灰度（color=gray 或 mono）是独立的属性。电子纸也可以是彩色的。

  • 电子纸会在画面变化后留下残影，因此光标和闪烁文字保持静止，光标无拖尾，动态图像停在当前帧，不确定进度条停止移动，键盘滚动直接跳转，也不进行会产生颗粒残影的抖动。Silkie 对每个电子纸窗口最多每秒提交十帧。程序通过 显示信息协议 获知 kind=eink，可自行减少动画和频繁重绘。

  • 电子纸和灰度显示器会对主题、配置档、launch --color、会话和程序的颜色应用高对比度文字配色。对于未启用电子纸模式的灰度显示器，color_scheme dark 使用黑底白字，其他设置使用白底黑字。灰度显示器按面板本身的灰阶显示图像。

若要让所有窗口都使用电子纸模式，请添加:

eink_mode yes

在此模式下，若 Silkie 内置表、monitor_info 和 display_info 均未声明显示器的颜色，Silkie 会将其视为灰度显示器。彩色电子纸可通过 monitor_info "<型号>" kind=eink color=rgb 或 display_info color=rgb 声明颜色。

在 Settings → Appearance → Color scheme → E-ink color scheme 中选择浅色（默认）、深色、跟随系统或反转系统。对应的配置选项为 eink_color_scheme。系统未报告偏好时，跟随和反转均使用浅色。此设置适用于彩色和单色电子纸。按 ctrl+shift+f12 切换普通显示器的配色，按 ctrl+shift+alt+f12 切换 eink_mode。这些快捷键使用 kitty_mod``（默认为 ``ctrl+shift），相同操作也可从命令面板调用。自定义快捷键的示例:

map f6 set_color_scheme toggle
map f7 set_eink_mode toggle

使用 color_scheme light 或 color_scheme dark 为普通显示器固定配色。set_color_scheme auto 恢复配置中的颜色和自动主题。显式选择浅色或深色优先于自动主题和系统外观变化。重新加载配置会恢复已保存的选择。

With color_scheme auto, Silkie follows the OS appearance: it uses dark-theme.auto.conf, light-theme.auto.conf or no-preference-theme.auto.conf from the Silkie config directory when present. With automatic_light_theme yes and no light theme file, a light OS appearance selects a built-in light theme, as long as silkie.conf sets no colors of its own; by default the colors stay as configured. To customize the built-in theme, copy builtin-light-theme.conf from the Silkie package to light-theme.auto.conf. Colors from profiles, launch --color, the ssh kitten and programs stay on top of any theme. The black on white of a gray display shows over all of them.

程序可以通过 显示信息协议 的 appearance 字段读取桌面外观偏好。桌面外观变化时，Silkie 会通知程序重绘，即使终端使用固定主题。

display_info declares properties of every display that only change what programs are told, for example display_info kind=eink reports e-paper without changing anything Silkie does.

Minimum contrast¶

minimum_contrast works like iTerm2's Minimum contrast: it makes text that is too close to its background readable, such as the dark ANSI blue of ls on a machine reached over ssh, on a black background. It is a percentage from 0 (off) to 100: the smallest difference in lightness allowed between text and its background. Closer text keeps its hue and becomes lighter or darker, colors that already stand out are not changed, and 100 leaves only black and white text:

minimum_contrast 40

It can differ per terminal: set it in a profile, for a tab in a session file with minimum_contrast 40, for a window with launch --minimum-contrast 40, or at runtime with kitten @ set-minimum-contrast 40 (--match-tab for a whole tab, default to remove the setting). A window's own setting wins over its tab's, then its profile's, then the option. Block elements, shades and Powerline separators are left alone, since programs draw pictures with them. On e-paper and grayscale displays it is what keeps colored text visible.

Display channel precision¶

The 显示信息协议 reports whether output is RGB, grayscale, or black-and-white, and the precision of each active channel. System-reported framebuffer precision does not prove physical panel precision or calibration. For a panel whose capabilities the system cannot report, declare them:

display_info color=rgb red_bits=5 green_bits=6 blue_bits=5

Use display_info color=gray gray_bits=4 for sixteen gray levels, or display_info color=mono for black and white. The report identifies these values as configured and uses zero for unknown widths. The display protocol documents the query, replies, subscriptions, and platform detection limits.

When the user changes the terminal's color scheme, profile colors, or output color capabilities, Silkie asks applications to redraw as it does after a window resize: it sends SIGWINCH to each affected terminal's foreground process group. Applications subscribed to in-band resize notifications also receive the usual resize report, with the current dimensions even if they have not changed. Existing color-scheme and display subscriptions keep working.

Moving a window between outputs can change the color model, channel precision, gamut, or HDR headroom and trigger the same redraw. Refresh-rate changes alone do not. Application-issued palette changes through OSC escape sequences do not send resize notifications, so an application's own redraw cannot cause a palette-change redraw loop.

字体与中日韩文本¶

Silkie 默认的 font_family 是 Iosevka。请安装 Iosevka，以及衬线字体角色所需的 Iosevka Slab。协议选择、字体下载链接和中日韩文本行为见 字体选择协议。应用不附带字体文件。

font_role

可重复指定的角色到字体映射，使用 kitty 的字体描述语法。默认为 sans Iosevka 和 serif Iosevka Slab。default 保留给 font_family。配置的角色可包含字体特性和可变轴设置；角色数量没有固定限制。

cjk_font

默认：auto。优先使用对应地区的 Sarasa Term、Noto Sans CJK 或 Noto Sans Mono CJK，再使用地区系统字体和平台字形回退。明确指定字体可覆盖这一偏好。

cjk_font_locale

默认：auto。选择 jp、kr、sc、tc 或 hk，以使用相应地区的中日韩字形。自动选择遵循进程的区域设置；未指定时默认为 sc。

输入限制¶

这些限制适用于程序写入终端的数据，每项都表示最大值。默认值 0 表示不限制。仅当需要约束试图耗尽内存或时间的程序时才应设置。Goblin View 使用 csi-limit 和 escape-limit；Goblin Skiff 使用 --csi-limit、--escape-limit 和 --vector-depth-limit。虚线、光栅和曲线限制适用于 Silkie 栅格化矢量图像时。

csi_limit

单条 CSI 序列的最大字节数，即 ESC [ 之后直到并包括最终字节的全部内容。更长的序列会被忽略。0 表示 CSI 长度不限。带数量参数的光标移动和编辑操作仍限制在屏幕范围内。

escape_limit

单条 OSC、APC、DCS、PM 或 SOS 序列的最大字节数，不计引入符和终止符。更长的序列会被丢弃。0 表示这些序列长度不限。剪贴板写入仍受 clipboard_max_size 限制。

vector_depth_limit

矢量元素可嵌套的最大分组层数。更深的元素不绘制。0 表示深度不限。无论如何设置，父级链中的循环都会被拒绝。

vector_dash_limit

单条路径描边的最大虚线边界数。若路径需要更多边界，则绘制为实线。0 表示绘制全部虚线。

vector_raster_limit

单个矢量图像光栅的最大像素数。请求的尺寸过大时按比例缩小。0 表示按实际显示尺寸栅格化。

vector_curve_limit

将一条曲线或一个圆展平时使用的最大线段数。0 表示按展平误差需要生成线段。

查找终端输出¶

选择 Edit → Find → Find…，即可搜索当前窗格可见的文字和回滚历史。在 macOS 上也可按 Cmd+F。用 Find Next 或在搜索框中按 Enter 查找更早的输出，用 Find Previous 或 Shift+Enter 查找较新的输出。Use Selection for Find 查找选中的文字。匹配项可以跨越自动换行处。

用 find_match_foreground 和 find_match_background 设置普通匹配项的前景色和背景色，用 find_current_foreground 和 find_current_background 设置当前匹配项的颜色。

压缩回滚历史¶

Silkie 默认使用 zstd 级别 9 保存不限行数的回滚历史，scrollback_lines 为 unlimited，scrollback_compression 为 9。可独立指定行数上限和压缩级别。压缩级别支持 none 和 zstd 的各级别，包括用于快速压缩的负数级别。

最新的 2048 行保持未压缩。更早的行每 128 行交给后台线程紧凑编码并压缩，输出无需等待压缩。以 benchmark.py 测试，吞吐量与未压缩时相同。150 万行彩色日志占用约 49 MB，未压缩时则为 8.4 GB。

这些设置可因窗口和标签页而异。

  • 配置档可设置 scrollback_lines 和 scrollback_compression。

  • launch --scrollback-lines N --scrollback-compression L`（也可用于会话文件中的 :code:`launch 行）为新窗口设置这些参数。同一标签页中之后创建的窗口继承这些设置。

  • kitten @ set-scrollback-compression L [--lines N] [--recompress] 修改匹配窗口的设置。用 --match-tab 可修改匹配标签页及其中之后创建的窗口。--recompress 还会在后台重新压缩已有的压缩历史。

新的级别适用于之后开始压缩的行。回滚历史没有行数上限时，没有行被移出，因此分页器历史（scrollback_pager_history_size）不会收到这些行。

scrollback_lines¶

设置新窗格的回滚行数上限。默认为 unlimited。

scrollback_compression¶

设置新窗格的 zstd 级别。默认为 9。用 none 可保持所有行未压缩。

hdr¶

默认：detect。

允许 HDR 显示器显示高于 SDR 白色的亮度。普通 SDR 内容与关闭此选项时完全相同；HDR 仅为程序通过 HDR 亮度协议、cursor_brightness 和 HDR 图像请求的内容增加亮度。默认值 detect 会在无需切换显示模式、且具备相应能力的显示器上启用 HDR：包括 macOS 上支持 EDR 的显示器（含 MacBook 内置显示器），以及 Wayland 上已经提供 HDR 亮度余量的显示器。窗口移到其他屏幕时会跟随显示器变化。no 禁用 HDR；auto 仅在屏幕上存在亮于 SDR 白色的内容时启用扩展范围；always 则不论检测结果都保持启用。Silkie 不会将显示器切换为 HDR 模式；需要这样做的外接显示器必须在系统显示设置中启用。修改此选项后请重启 Silkie。支持 macOS；Wayland 还需要合成器实现色彩管理，并由图形驱动提供浮点窗口表面，详见 HDR 亮度协议。

hdr_max_headroom¶

默认：4.0。

Silkie 用于 HDR 内容的最大亮度，以 SDR 白色的倍数表示。显示器可能提供更大的亮度余量，尤其在较低亮度设置下，但过亮的文本不适合阅读。超出此值的请求会被钳制。显示器自身的限制始终适用。

cursor_brightness¶

默认：1.0。

The brightness of the block cursor as a multiple of SDR white, so 2.0 makes it twice as bright as normal white text. Values above one only take effect on an HDR display with hdr enabled, otherwise the cursor is rendered as usual. See HDR 亮度协议. The minimum is 1.0. Settings increases or decreases this multiplier in steps of 0.1.

wayland_colorspace¶

默认：srgb。

Wayland 上操作系统窗口所用的色彩空间。默认 srgb 保持原有行为。displayp3 或 rec2020 会告知合成器窗口属于相应广色域；程序标注了广色域的颜色和图像会在该色域显示，而非裁剪到 sRGB，详见 广色域颜色。auto 在三者中选择窗口所在显示器能够完整显示的最宽色域。所有未标注色域的内容均按 sRGB 处理并保持原貌，这与 macos_colorspace 不同。需要合成器支持色彩管理；否则窗口保持 sRGB。广色域窗口会额外对像素执行一次处理。

eink_mode¶

默认：no。

Treat every Silkie window as being on e-paper, whatever monitor it is on. Usually this is not needed: Silkie recognizes the e-paper monitors in its built-in table, and monitor_info declares others, for the windows on that monitor only, so that a window moved to an ordinary monitor looks ordinary again.

A window on e-paper reports kind=eink through the display protocol and avoids what makes such a panel ghost: the cursor and text do not blink, there is no cursor trail, animated images stay on the frame they show, an indeterminate progress bar does not move, keyboard scrolling jumps rather than glides, and the output is not dithered. For now custom_shaders, the visual bell and pixel_scroll stay as configured. Silkie submits at most ten frames per second on e-paper. Images are reduced to the levels of gray by the monitor. The eink_color_scheme setting chooses the foreground and background on both color and monochrome e-paper. With this option a display whose colors nothing declares, in the built-in table, monitor_info or display_info, is taken to show gray, as before. For color e-paper declare its colors, for example display_info color=rgb.

Switch at runtime with set_eink_mode yes, no or toggle; the default shortcut is ctrl+shift+alt+f12. Display subscribers receive the change. Reloading the configuration restores the configured setting. This option takes precedence over kind=... in display_info and monitor_info.

eink_color_scheme¶

Default: light.

Color scheme for windows on e-paper. Choose light for black on white, dark for white on black, follow_os to follow the desktop, or invert_os to use the opposite desktop appearance. When the desktop has no preference, both OS-based choices use light. The setting applies to both monochrome and color e-paper and is available under Color scheme in Settings.

monitor_info¶

默认：空（不覆盖）。

Properties of one monitor that the operating system cannot report, for the windows on that monitor. The first word selects the monitor, quoted when it has spaces, and the rest are key=value pairs with the keys of display_info:

monitor_info MIRA253 kind=eink color=gray bits=4
monitor_info "OBX:0x0011" kind=eink color=gray
monitor_info DP-7 kind=eink color=rgb

A monitor is selected by its EDID manufacturer ID and product code as MFG:PRODUCT, with the product code in decimal or in hex with 0x, or MFG:* for every product of the manufacturer; or else by its model (the name the system gives, or the EDID name descriptor), the name of its connector, such as DP-7, or its make, each compared whole and without regard to case; or by a part of the description the system gives of it. Serial numbers are not used, as they say whose monitor it is. kitten @ ls shows these for the monitor of each OS window, and silkie --debug-rendering logs them when a window moves to another monitor.

Unlike display_info, which only changes what programs are told, this changes what Silkie does: a monitor declared kind=eink gets the e-paper behavior described for eink_mode, and one declared color=gray or mono gets a high-contrast palette. The two are independent, so color e-paper is kind=eink color=rgb. Declarations here override the built-in table of e-paper monitors and what the operating system says. Use this option once per monitor; when several lines select a monitor, each key takes its value from the last of them. display_info still overrides what programs are told.

color_scheme¶

默认：auto。

Use light for black text on white or dark for white text on black. These built-in high contrast schemes also set cursor, selection and tab colors. auto uses your configured colors and automatic theme files. E-paper uses eink_color_scheme.

Switch at runtime with set_color_scheme light, dark, auto or toggle. The default shortcut is ctrl+shift+f12. Changes apply on ordinary displays until the configuration is reloaded. Applications that subscribe to kitty's color preference notifications are notified.

display_info¶

默认：空（不覆盖）。

用于补充操作系统无法报告的显示属性，回答通过 显示协议 发起查询的程序。以空格分隔的 key=value 键值对会覆盖 Silkie 的检测结果，例如电子墨水显示器：:

display_info kind=eink color=gray bits=4

The keys are kind (lcd, oled, eink or unknown), color (rgb, gray or mono), bits (a common width for all active color channels), red_bits, green_bits, blue_bits, gray_bits, gamut (srgb, p3, rec2020 or unknown), headroom, scale, period (refresh period in microseconds) and ppi.

Individual channel widths override bits regardless of order. For RGB565, use color=rgb red_bits=5 green_bits=6 blue_bits=5; the report's legacy bits is then zero because the channels differ. A grayscale display uses color=gray gray_bits=4 for sixteen levels. color=mono always means one bit; use gray for more than two levels.

The report identifies declared precision as configured, and precision from Silkie's table of monitors as model. Detected framebuffer widths are labeled framebuffer, since they do not establish physical panel precision or color calibration. Unknown channel widths are zero.

This option applies to every monitor and only changes what programs are told, not what Silkie does; monitor_info declares the properties of one monitor and acts on them.

tablet_hardware_ids¶

默认：no。

是否允许通过 数位板指针协议 告知程序笔和数位板的硬件标识：笔的序列号、类型标识，以及数位板的厂商和产品 ID。序列号可识别笔的所有者，而查询程序可能运行在另一台机器上，因此默认拒绝通过模式位 8 请求这些信息：读回的该位为关闭，且不发送标识。笔、数位板和控制板的其他信息仍照常报告。

haptic_feedback¶

默认：yes。

允许程序在触控板上播放触觉反馈，参阅 触觉反馈协议。仅适用于 macOS。

high_contrast¶

默认：auto。

The high contrast hint sent to terminal programs. auto follows the desktop accessibility setting and requests high contrast on e-paper. off and on explicitly set the hint to 0 or 1.

differentiate_without_color¶

默认：auto。

The differentiate without color hint sent to terminal programs. auto follows the macOS accessibility setting and always enables the hint on grayscale and monochrome displays. off and on explicitly set the hint to 0 or 1.

magnify_raster_resolution¶

默认：yes。

During accessibility zoom, round the reported raster scale up to a whole number, capped at three times the base size, once a raster image becomes visible. Applications can use resize notifications to send an image at the reported resolution. Set this to no to save bandwidth by reporting the base pixel size. Silkie scales the available image to the selected zoom level.

deep_color¶

Default: always.

Draw into a window surface with more than 8 bits per color channel, so that smooth gradients, in images with 16 bits per channel for example, do not band on displays that show more than 256 levels. This does not make anything brighter, that is hdr. With the default, always, Silkie asks for a deep surface wherever the system has one, and how finely it dithers into it follows the display the window is on, see output_dither. never keeps an 8 bit surface, to save memory and bandwidth.

What a deep surface costs differs. On Wayland and X11 it has 10 bits per channel and the same 32 bits per pixel as an 8 bit one, so it costs nothing more. Its alpha has at most 2 bits, so a transparent window gets a floating point surface on Wayland, where the graphics driver has one, and stays 8 bit otherwise. On X11 it needs a visual of depth 30. On macOS it is a floating point surface with 16 bits per channel, twice the memory and bandwidth of an 8 bit one, on every screen; on a screen not known to show more than 8 bits it is dithered to 8 bit steps. Set never to save that bandwidth. With macos_colorspace set to default the colors are passed to the display unmanaged, which a floating point surface cannot do, so that window stays 8 bit.

HDR needs a floating point surface too: while hdr is in use for a window, which with the default detect is whenever it is on an HDR capable screen, such as a MacBook Pro's, the window has one even with never, and on macOS switches to and from it, like a resize, as it is moved between screens. Set hdr to no as well to keep every window 8 bits deep.

The surface Silkie actually got, and how it dithers, is reported by the 显示信息协议 as output_bits, output_type and output_dither. On Wayland and X11 the choice is made for newly created OS windows.

output_dither¶

默认：yes。

Instead of rounding the colors Silkie computes with more precision than the display shows, such as gradients in images with 16 bits per channel, scaled images and the edges of text, to the nearest step, which shows as bands, add a faint ordered dither, below half a step. Colors that are exactly a step, solid text and backgrounds among them, are left exactly as they are. The step is that of the window surface when it is 8 bits deep. A deeper surface is dithered to the steps of 8 bits unless the system says the display the window is on shows more, since compositors and the system round a deep surface to an 8 bit display without dithering it. Then a 10 bit surface is dithered to its own steps and a floating point one is not dithered at all. The system says so for HDR outputs on Wayland, for screens that support extended dynamic range or report more than 8 bits on macOS, and for screens 30 bits deep on X11. Dithering draws a window through an intermediate image, which costs one more pass over the window for every frame.
