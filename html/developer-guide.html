Writing software for Silkie¶

Silkie is a fork of the kitty terminal emulator. kitty extends the traditional VT/xterm-style terminal protocol with its own graphics, keyboard, and other protocols. Kittens are kitty’s companion tools and plugins; they use terminal capabilities and can add functionality to kitty. Silkie adds further terminal protocols and the show_pointer tool.

Silkie’s behavior is documented in several places: terminal standards, kitty’s manuals, and Silkie’s extension specifications. This guide links to each source and the relevant implementation files.

Source and version¶

Silkie’s source is on the silkie branch.

Upstream kitty manuals may describe behavior that differs from your Silkie build. The source for your version shows how a feature is implemented. Runtime capability queries tell your application which extensions, versions, and optional features are available.

Getting started¶

If you are new to kitty, the kitty overview introduces the terminal, and the kitten overview introduces its tools and plugins. The terminal foundations and inherited kitty protocols below cover the standards and protocols that Silkie builds on.

To add a Silkie feature to your application, start with Extension capabilities protocol and OSC 777 extension framing, then choose the protocols you need from the Silkie extension map. Each specification explains how to discover support, use the feature, and clean up afterward, including any platform limits. Test your application in the target terminal and provide a fallback when a feature is unavailable.

For kittens, terminal user interfaces, remote-control clients, and shell integration, see kitten and application APIs. The implementation map points to the relevant code if you want to investigate behavior or contribute a change to Silkie.

Terminal foundations¶

The compatibility model is a terminal receiving text and control sequences over a byte stream. The following references explain the inherited vocabulary; they are not a claim that Silkie implements every historical terminal feature.

  • ECMA-48: control functions defines control-function syntax, including CSI, SGR, OSC, and string terminators.

  • XTerm control sequences covers the VT/xterm conventions used for cursor movement, screen modes, mouse reporting, and other common terminal interactions.

  • Silkie’s terminfo source describes the capabilities advertised to terminfo-based applications.

Capability discovery and cleanup¶

Query support before enabling an optional mode, apply a timeout when no reply arrives, and keep a fallback for unsupported features. The OSC 777 capability registry covers its selector family; graphics formats, SGR additions, and other protocols have their own discovery rules in their specifications. Disable modes you enabled when exiting or suspending, as the protocol requires. Account for remote connections and multiplexers: the application’s effective capabilities depend on the whole path to the terminal.
