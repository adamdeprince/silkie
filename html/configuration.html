Silkie configuration¶

Silkie reads silkie.conf from its own configuration directory, normally ~/.config/silkie/. It does not automatically read kitty’s configuration or use KITTY_CONFIG_DIRECTORY.

Configuration paths¶

Set SILKIE_CONFIG_DIRECTORY to use a different directory. Otherwise, Silkie searches for silkie.conf in the following order and uses the first file whose directory is writable:

  • $XDG_CONFIG_HOME/silkie/, when XDG_CONFIG_HOME is set;

  • ~/.config/silkie/;

  • ~/Library/Preferences/silkie/ on macOS;

  • silkie/ under each directory in XDG_CONFIG_DIRS, in order.

If no configuration exists, Silkie creates $XDG_CONFIG_HOME/silkie/ or ~/.config/silkie/. System defaults come from /etc/xdg/silkie/silkie.conf and are read before the user configuration. Relative includes, themes, kitten configuration files, and profiles use the Silkie configuration directory. The Settings window writes settings.conf there, which is read after silkie.conf.

Use --config /path/to/file.conf to load a file explicitly, or --config NONE to skip configuration files. To reuse existing kitty settings, copy them to silkie.conf or add an explicit include, for example:

include ../kitty/kitty.conf

The configuration syntax and inherited settings are described in kitty’s configuration reference. The paths above are specific to Silkie.

Environment variables lists the environment variables that Silkie reads and the ones it sets for the programs running in it.

Quitting on macOS¶

Silkie does not bind Cmd-Q to quit by default. To explicitly enable it, add this to silkie.conf:

map cmd+q quit

The application menu’s Quit command remains available without a keyboard shortcut unless you configure one.

Spatial display¶

On macOS, View → Spatial Display switches between ordinary rendering, stereo content that follows the head, and an anchored terminal wall. Settings place XREAL 1S support under Experimental and untested, disabled by default. Enable experimental_xreal_1s yes to use side-by-side output or XREAL tracking. Red/blue output without tracking does not require that opt-in. Spatial settings include side-by-side and red/blue output, independent positive and negative divergence limits, and a 2^X divergence multiplier with X from -6 to 6 in 0.1 steps. Fractional pixel depth scales with the physical eye resolution, including Retina backing scale. Negative divergence and vertical phase are disabled by default and require explicit user configuration. Applications can assign depth to text and graphics while leaving unmarked content flat. See Spatial display and depth for XREAL setup, configuration, the optional text attribute, and current tracking support.

Numeric controls enforce the setting’s domain: opacity stays within its documented range, dimensions and durations are nonnegative, and documented negative sentinels and signed scroll multipliers remain available. Cursor HDR brightness and HDR headroom start at 1× and step by 0.1, with no invented upper bound. Composite values retain their complete text rather than losing optional parameters to a numeric widget.

SSH agent forwarding¶

Set ssh_agent_forwarding yes to offer the local SSH agent over the terminal channel. Odin Seat and Skiff can keep a stable SSH_AUTH_SOCK while the provider follows the attached terminal. See SSH agent transport for permissions, connection lifetime, fallback behavior, and protocol details.

The option defaults and descriptions below come from Silkie’s configuration definitions.

E-paper and color switching¶

Silkie knows which monitor each window is on, and treats a window on an e-paper monitor as such, even when the operating system thinks it is an ordinary display, as it does for every e-paper monitor seen so far. It knows some e-paper monitors by the model in their EDID, never by serial number (among them the ONYX BOOX Mira and Mira Pro, several DASUNG Paperlike models and the Modos Glider). Declare any other with monitor_info in silkie.conf, by its model, connector, EDID manufacturer and product code, or a part of its description:

monitor_info MIRA253 kind=eink color=gray bits=4
monitor_info "OBX:0x0011" kind=eink color=gray
monitor_info DP-7 kind=eink color=rgb

kitten @ ls shows what Silkie knows of the monitor of each OS window, under display, and silkie --debug-rendering logs it when a window moves to another monitor. What follows applies to the windows on that monitor only: a window dragged to an ordinary monitor looks and behaves as usual again once it has stayed there for a moment, and comes back when it returns.

E-paper (kind=eink) and gray (color=gray or mono) are independent, as there is color e-paper:

  • On e-paper, which ghosts when it changes, the cursor and blinking text do not blink, there is no cursor trail, animated images stay on the frame they show, an indeterminate progress bar stands still, a keyboard scroll jumps rather than glides and the output is not dithered, since dither shows as grain that ghosts. For now custom shaders, the visual bell, pixel scrolling and the repaint timing stay as configured. Programs are told kind=eink through the Display protocol, so that they can avoid animation and frequent redraws themselves.

  • On a display that shows only gray, text is black on white, or white on black with color_scheme dark, over the colors of themes, profiles, launch --color, sessions and programs, which come back when the window moves to another display. Images are shown as they are, and the monitor reduces them to its levels of gray.

To treat every window as on e-paper whatever its monitor, add:

eink_mode yes

With it a display whose colors nothing declares, in Silkie’s table, monitor_info or display_info, is taken to show gray, so a color e-paper monitor needs its colors declared, for example monitor_info "<its model>" kind=eink color=rgb or display_info color=rgb.

Press ctrl+shift+f12 to switch between black on white and white on black. The display is still reported as e-paper in either scheme. Press ctrl+shift+alt+f12 to toggle eink_mode. These shortcuts use kitty_mod (by default ctrl+shift). The actions are also available from the command palette. To choose your own shortcuts:

map f6 set_color_scheme toggle
map f7 set_eink_mode toggle

Use color_scheme light or color_scheme dark for a persistent color choice on any display. set_color_scheme auto returns to configured colors and automatic themes. Explicit light and dark choices take precedence over automatic themes and OS appearance changes. Reloading the configuration restores the saved choices.

With color_scheme auto, Silkie follows the OS appearance: it uses dark-theme.auto.conf, light-theme.auto.conf or no-preference-theme.auto.conf from the Silkie config directory when present. With automatic_light_theme yes and no light theme file, a light OS appearance selects a built-in light theme, as long as silkie.conf sets no colors of its own; by default the colors stay as configured. To customize the built-in theme, copy builtin-light-theme.conf from the Silkie package to light-theme.auto.conf. Colors from profiles, launch --color, the ssh kitten and programs stay on top of any theme. The black on white of a gray display shows over all of them.

display_info declares properties of every display that only change what programs are told, for example display_info kind=eink reports e-paper without changing anything Silkie does.

Minimum contrast¶

minimum_contrast works like iTerm2’s Minimum contrast: it makes text that is too close to its background readable, such as the dark ANSI blue of ls on a machine reached over ssh, on a black background. It is a percentage from 0 (off) to 100: the smallest difference in lightness allowed between text and its background. Closer text keeps its hue and becomes lighter or darker, colors that already stand out are not changed, and 100 leaves only black and white text:

minimum_contrast 40

It can differ per terminal: set it in a profile, for a tab in a session file with minimum_contrast 40, for a window with launch --minimum-contrast 40, or at runtime with kitten @ set-minimum-contrast 40 (--match-tab for a whole tab, default to remove the setting). A window’s own setting wins over its tab’s, then its profile’s, then the option. Block elements, shades and Powerline separators are left alone, since programs draw pictures with them. On e-paper and grayscale displays it is what keeps colored text visible.

Display channel precision¶

The Display protocol reports whether output is RGB, grayscale, or black-and-white, and the precision of each active channel. System-reported framebuffer precision does not prove physical panel precision or calibration. For a panel whose capabilities the system cannot report, declare them:

display_info color=rgb red_bits=5 green_bits=6 blue_bits=5

Use display_info color=gray gray_bits=4 for sixteen gray levels, or display_info color=mono for black and white. The report identifies these values as configured and uses zero for unknown widths. The display protocol documents the query, replies, subscriptions, and platform detection limits.

When the user changes the terminal’s color scheme, profile colors, or output color capabilities, Silkie asks applications to redraw as it does after a window resize: it sends SIGWINCH to each affected terminal’s foreground process group. Applications subscribed to in-band resize notifications also receive the usual resize report, with the current dimensions even if they have not changed. Existing color-scheme and display subscriptions keep working.

Moving a window between outputs can change the color model, channel precision, gamut, or HDR headroom and trigger the same redraw. Refresh-rate changes alone do not. Application-issued palette changes through OSC escape sequences do not send resize notifications, so an application’s own redraw cannot cause a palette-change redraw loop.

Fonts and CJK text¶

Silkie’s default font_family is Iosevka. Install Iosevka and, for the serif role, Iosevka Slab. See Font selection protocol for protocol selection, font installation links and CJK behavior. Font files are not bundled.

font_role

Repeatable role-to-font mappings, using kitty’s font specification syntax. The defaults are sans Iosevka and serif Iosevka Slab. default is reserved for font_family. Configured roles can carry features and variable-axis settings, and there is no fixed role count.

cjk_font

Default: auto. Prefer regional Sarasa Term, Noto Sans CJK or Noto Sans Mono CJK, then regional system fonts and platform glyph fallback. An explicit font specification overrides that preference.

cjk_font_locale

Default: auto. Choose jp, kr, sc, tc or hk for regional CJK glyph forms. Automatic selection follows the process locale, defaulting to sc when unspecified.

Input limits¶

These limits apply to data a program writes to the terminal. Each one is a maximum. 0, the default, means there is no limit. Set one only to contain a program that tries to exhaust memory or time. Goblin View uses csi-limit and escape-limit. Goblin Skiff uses --csi-limit, --escape-limit and --vector-depth-limit. The dash, raster and curve limits apply when Silkie rasterizes a vector image.

csi_limit

The maximum number of bytes in one CSI sequence, everything after ESC [ up to and including its final byte. A longer sequence is ignored. 0 means a CSI may be of any length. Cursor motion and editing that name a count are still clamped to the screen.

escape_limit

The maximum number of bytes in one OSC, APC, DCS, PM or SOS sequence, not counting its introducer and terminator. A longer sequence is discarded. 0 means these sequences may be of any length. Clipboard writes are still bounded by clipboard_max_size.

vector_depth_limit

The maximum number of groups a vector element may be nested inside. Deeper elements are not drawn. 0 means any depth. A cycle in the parent chain is rejected either way.

vector_dash_limit

The maximum number of dash boundaries stroked for one path. A path that would need more is drawn solid. 0 means every dash is stroked.

vector_raster_limit

The maximum number of pixels in the raster of one vector image. A larger requested size is scaled down to fit. 0 means the image is rasterized at the size it is shown.

vector_curve_limit

The maximum number of line segments used to flatten one curve or circle. 0 means as many segments as the flattening error asks for.

Compressed scrollback¶

Silkie keeps unlimited scrollback by default, compressed with zstd at level 9: scrollback_lines is unlimited and scrollback_compression is 9. The two options are independent: a line limit, compression (none or any zstd level, negative fast levels included) or both. The option documentation has the measured memory, CPU and latency for several levels, and what frames and a line limit cost.

The newest 2048 lines stay uncompressed. Older lines go, 128 at a time, to a background thread that encodes them compactly and compresses them, so output does not wait for compression: benchmark.py measured the same throughput as uncompressed scrollback. 1.5 million lines of colored log output take about 49 MB instead of 8.4 GB.

The settings can differ per window and per tab:

  • a profile can set scrollback_lines and scrollback_compression;

  • launch --scrollback-lines N --scrollback-compression L (also on a launch line of a session file) sets them for the new window, and windows opened later in its tab get the same;

  • kitten @ set-scrollback-compression L [--lines N] [--recompress] changes them for the matched windows, or with --match-tab for tabs, including windows opened in them later. --recompress also recompresses what is already compressed, in the background.

A new level applies to lines compressed from then on. With unlimited scrollback the scrollback pager history (scrollback_pager_history_size) receives nothing, as no line ever leaves the scrollback.

hdr¶

Default: detect.

Allow colors brighter than SDR white on HDR displays. Normal (SDR) content is rendered exactly as it is with this option off, HDR only adds extra brightness requested by programs via the HDR brightness protocol, by cursor_brightness and by HDR images. The default, detect, keeps HDR enabled on displays where it is available without switching display modes: EDR-capable displays on macOS, including built-in MacBook displays, and displays already offering HDR headroom on Wayland. This follows the display as the window moves between screens. no disables HDR. auto enables the extended range only while something brighter than SDR white is on screen; always keeps it enabled regardless of display detection. Silkie does not switch a display into HDR mode; an external display that requires this must be enabled in the system’s display settings. Restart Silkie after changing this option. Supported on macOS, and on Wayland where the compositor implements color management and the graphics driver has floating point window surfaces, see HDR brightness protocol.

hdr_max_headroom¶

Default: 4.0.

The maximum brightness, as a multiple of SDR white, that Silkie will use for HDR content. The display may offer more headroom than this, particularly at low brightness settings, but very bright text is unpleasant to look at. Requests for more brightness are clamped to this value. The display’s own limit always applies.

cursor_brightness¶

Default: 1.0.

The brightness of the block cursor as a multiple of SDR white, so 2.0 makes it twice as bright as normal white text. Values above one only take effect on an HDR display with hdr enabled, otherwise the cursor is rendered as usual. See HDR brightness protocol. The minimum is 1.0. Settings increases or decreases this multiplier in steps of 0.1.

wayland_colorspace¶

Default: srgb.

The colorspace OS windows are drawn in on Wayland. With the default of srgb a window is what it always was. With displayp3 or rec2020 the compositor is told the window is in that wider gamut, and colors and images that a program tags with a wide gamut, see Wide gamut colors, are shown in it rather than being clipped to sRGB. auto picks the widest of the three that the display the window is on can show in full. Everything that is not tagged with a gamut is sRGB and keeps its appearance, unlike with macos_colorspace. This needs a compositor that implements color management, on any other the window stays sRGB. A wide window is drawn with one extra pass over its pixels.

eink_mode¶

Default: no.

Treat every Silkie window as being on e-paper, whatever monitor it is on. Usually this is not needed: Silkie recognizes the e-paper monitors in its built-in table, and monitor_info declares others, for the windows on that monitor only, so that a window moved to an ordinary monitor looks ordinary again.

A window on e-paper reports kind=eink through the display protocol and avoids what makes such a panel ghost: the cursor and text do not blink, there is no cursor trail, animated images stay on the frame they show, an indeterminate progress bar does not move, keyboard scrolling jumps rather than glides, and the output is not dithered. For now custom_shaders, the visual bell, pixel_scroll and the repaint timing stay as configured, and images are not reduced to the levels of gray of the panel, which the monitor does itself. Being e-paper does not make a display monochrome, as there is color e-paper. Black text on white, or white on black with an explicit color_scheme dark, follows from a display that shows only gray (color=gray or mono). With this option a display whose colors nothing declares, in the built-in table, monitor_info or display_info, is taken to show gray, as before. For color e-paper declare its colors, for example display_info color=rgb.

Switch at runtime with set_eink_mode yes, no or toggle; the default shortcut is ctrl+shift+alt+f12. Display subscribers receive the change. Reloading the configuration restores the configured setting. This option takes precedence over kind=... in display_info and monitor_info.

monitor_info¶

Default: empty (no overrides).

Properties of one monitor that the operating system cannot report, for the windows on that monitor. The first word selects the monitor, quoted when it has spaces, and the rest are key=value pairs with the keys of display_info:

monitor_info MIRA253 kind=eink color=gray bits=4
monitor_info "OBX:0x0011" kind=eink color=gray
monitor_info DP-7 kind=eink color=rgb

A monitor is selected by its EDID manufacturer ID and product code as MFG:PRODUCT, with the product code in decimal or in hex with 0x, or MFG:* for every product of the manufacturer; or else by its model (the name the system gives, or the EDID name descriptor), the name of its connector, such as DP-7, or its make, each compared whole and without regard to case; or by a part of the description the system gives of it. Serial numbers are not used, as they say whose monitor it is. kitten @ ls shows these for the monitor of each OS window, and kitty --debug-rendering logs them when a window moves to another monitor.

Unlike display_info, which only changes what programs are told, this changes what Silkie does: a monitor declared kind=eink gets the e-paper behavior described for eink_mode, and one declared color=gray or mono black text on white. The two are independent, so color e-paper is kind=eink color=rgb. Declarations here override the built-in table of e-paper monitors and what the operating system says. Use this option once per monitor; when several lines select a monitor, each key takes its value from the last of them. display_info still overrides what programs are told.

color_scheme¶

Default: auto.

Use light for black text on white or dark for white text on black. These built-in high contrast schemes also set cursor, selection and tab colors. auto uses your configured colors and automatic theme files, except that eink_mode selects the light scheme.

Switch at runtime with set_color_scheme light, dark, auto or toggle. The default shortcut is ctrl+shift+f12. Changes apply to all windows, including new windows, until the configuration is reloaded. Applications that subscribe to kitty’s color preference notifications are notified.

display_info¶

Default: empty (no overrides).

Properties of the display that the operating system cannot report, used to answer programs that ask with the display protocol. A space separated list of key=value pairs that override what Silkie detects, for example on an e-ink display:

display_info kind=eink color=gray bits=4

The keys are kind (lcd, oled, eink or unknown), color (rgb, gray or mono), bits (a common width for all active color channels), red_bits, green_bits, blue_bits, gray_bits, gamut (srgb, p3, rec2020 or unknown), headroom, scale, period (refresh period in microseconds) and ppi.

Individual channel widths override bits regardless of order. For RGB565, use color=rgb red_bits=5 green_bits=6 blue_bits=5; the report’s legacy bits is then zero because the channels differ. A grayscale display uses color=gray gray_bits=4 for sixteen levels. color=mono always means one bit; use gray for more than two levels.

The report identifies declared precision as configured, and precision from Silkie’s table of monitors as model. Detected framebuffer widths are labeled framebuffer, since they do not establish physical panel precision or color calibration. Unknown channel widths are zero.

This option applies to every monitor and only changes what programs are told, not what Silkie does; monitor_info declares the properties of one monitor and acts on them.

tablet_hardware_ids¶

Default: no.

Whether a program may be told the hardware identifiers of pens and tablets with the Tablet pointer protocol: the serial number of a pen, the identifier of its type, and the vendor and product ids of a tablet. A serial number tells whose pen it is, and the program asking may be running on another machine, so by default a program that asks for them with bit 8 of the mode is refused: the bit reads back as off and no identifier is sent. Everything else about a pen, a tablet or a pad is reported as before.

haptic_feedback¶

Default: yes.

Allow programs to play haptic feedback on the trackpad, see Haptic feedback protocol. Only available on macOS.
